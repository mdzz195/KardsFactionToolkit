# UE 配套资源

以默认罗马尼亚配置为例，三层数据必须一致：

| 层 | 值 |
| --- | --- |
| DLL 中的枚举 | `EFactionEnum::Romania = 13` |
| 蓝图与卡牌中的国家枚举 | `Romania`，数值 `13` |
| 游戏内部字符串 | `Romania` |
| 牌组编码字符 | `b` |
| 名称表显示文字 | `罗马尼亚` 或相应本地化内容 |

## 推荐顺序

1. 备份将修改的资源。编辑器使用与游戏版本匹配的类型声明；只追加国家枚举，保留原国家数值。DLL 的枚举扩展不涉及给 `BaseCardObject` 添加字段。
2. 为 `DT_FactionNames` 和 `DT_FactionIconTextures` 补齐该国家条目。图标字段需引用实际纹理对象，文件名文字不等于资产引用。彩色、黑白、空军图标按各自用途配置。
3. 检查国家函数库中的盟国判定、枚举循环上界、图标映射及默认分支。原版硬编码的国家数量不会因为 DLL 扩展自动改变。
4. 在 `W_CreateDeck` 放置该国家自己的按钮实例，给实例传入 `Romania`；修改共享按钮类会影响使用该类的全部实例。`selectFactionButton_Widget` 的名称、图标和点击绑定要保留正确输入。
5. 处理收藏与组卡两处筛选入口。`W_CollectionFilters` 的动态循环和 `W_DeckBuilder_FilterWidget` 的静态控件树属于不同位置。默认逻辑可能按卡组主国/盟国隐藏其他筛选按钮，这是界面规则，需要结合预期测试。
6. 设置实际卡牌的国家，处理资产注册表、资源路径和打包。编辑器占位依赖与真正修改资源应分开；原游戏已经提供的依赖不要用空占位包覆盖。
7. 先确认原生日志，再检查按钮显示、卡牌筛选、主国/盟国组合和牌组编码保存/读取。

## 边界

- `display_name` 仅进入构建清单，不会给 UE 自动生成名称表。
- 本项目不包含游戏导出的头文件、蓝图、图标、运行时库补丁或 PAK。
- 本项目不处理服务器对国家的认可，也不把某个旧国家替换成新国家。
- 新增主国还需要总部、卡背、进度等多处资源与逻辑；当前 DLL 工具以盟国为使用目标。
- 重构/还原 Widget 时要保留原字段类型与顺序、控件绑定、动画和委托结构。存在按钮不表示蓝图序列化结构一定正确。
